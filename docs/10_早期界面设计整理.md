## 4. 仍有效的需求与过时技术口径

仍有效的需求，是当前代码继续支持的目标或应当保留的边界：

- 门户负责模块分流，入口状态应与可跳转性一致；统计占位与真实 API 数据分开理解。
- 深色视觉、共享色彩变量、适量交互反馈和减少动态效果偏好继续有效；已有浅色资源按既定决策保留。
- Notes 按知识点组织内容、展示前置与后续关系，支持搜索、打开阅读、编辑和 Markdown 导入；这些用户目标不依赖力导向算法。
- Vault 保留早期静态展示资源，Newsletter 仍不承诺订阅服务。
- Notes 仍为内存演示。未来如果要长期管理笔记，应先确定持久化方式和关系数据模型，而不是把当前“保存”误称为落库。

以下旧技术或验收口径不应再直接指导开发：

1. **Verlet 物理循环及精确参数**：已退役，当前是阶段坐标和显式依赖边；不恢复旧阻尼、碰撞、扇区与漂移作为整理任务。
2. **hash 路由与单 `/notes` 页面假设**：当前为 history 路由与四专题，`/notes` 只承担重定向。
3. **首页完整落地页 + 完全静态无 API**：内容已分流至 Vault，Dashboard 混合真实接口与静态展示。
4. **“双主题已完成并有 LocalStorage”**：只代表历史记录，当前为暗色锁定和提示按钮。旧浅色 `#fcfbfa` / `#f4f2ee` 也不能当成当前颜色真值；当前 `.theme-light` 的 surface 为 `#f8f5f2`，具体值以样式表为准。
5. **“抽屉”“脉冲高亮”“绝不交叉”**：名称、残留变量和旧 CSS 不等于当前用户可触达行为，应以模板绑定和活跃代码链为准。
6. **“正则解析 = 完整 Markdown / YAML / 数学渲染”**：当前只是有限语法支持；Notes 内的教程代码块是文章内容，不能当成项目真实技术依赖或部署方案。
