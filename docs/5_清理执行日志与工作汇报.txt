## 3. H2（回测不可用）的真实状态：代码已修好，卡在数据源

这是今晚最重要的发现，**结论与 `docs/4` 的原始判断不同**。

### 3.1 修复掉了两层

1. **原症状**：`POST /api/tradesim/v1/simulate/run` → **503**，detail 为"TradeSim 行情依赖未安装…"
2. 装 `akshare` 后 → 503 消失，改为 **500 + ImportError（缺 pyarrow）**
3. 装 `pyarrow` 后 → 503 与 ImportError **全部消失**，请求真正进入了行情获取环节

**代码路径现在是正确的。** 这一步是实打实的修复。

### 3.2 但现在卡在数据源：东财历史 K 线接口不可达

装完依赖后实测返回 **400 `无法获取代码 000400 在指定日期范围内的数据`**，后端日志根因是：

```
requests.exceptions.ConnectionError: ('Connection aborted.',
  RemoteDisconnected('Remote end closed connection without response'))
```

我做了逐层定位（**已停止继续尝试，避免触发更严限流**）：

| 探测 | 结果 | 说明 |
|---|---|---|
| TCP 连 `push2his.eastmoney.com:443` | **可连** | 网络层没问题 |
| `https://push2his.eastmoney.com/`（根路径） | **404** | TLS/HTTP 完全正常，主机活着 |
| 目标接口 `/api/qt/stock/kline/get?...` | **被远端直接断开**（`RemoteDisconnected`） | 问题只在这一个路径 |
| 同一路径带浏览器 UA | 同样断开 | 不是 UA 问题 |
| 用 `curl_cffi` 模拟 Chrome TLS 指纹 | 同样断开（`curl: (56) Connection closed abruptly`） | **不是 TLS 指纹问题** |
| 换**另一个**东财接口 `push2.eastmoney.com/api/qt/clist/get` | **HTTP 200，返回真实数据**（total 1641 只股票） | 东财整体可用，**只有历史 K 线接口被丢包** |
| 经代理 7897 访问 | `ProxyError` | 代理侧也连不上该主机 |

**判定**：这不是项目代码缺陷，也不是依赖问题，而是**该机器到东财历史行情接口的链路被中断**。可能是：运营商/中间设备对该路径的干扰、东财对该接口的反爬策略、或我的连续请求触发了临时封禁。

**另需注意**：`data_fetcher.py:34-36` 会在调 akshare 前**主动摘掉代理变量**（`:86-88` 再恢复）。它用的是 `ak.stock_zh_a_hist`（`data_fetcher.py:43`，东财源）。代码逻辑本身没问题。

### 3.3 三条可选出路（**需要你定，我没动代码**）

1. **换数据源**：akshare 还有新浪源（`stock_zh_a_daily`）等其它接口，可加一条降级链。属新增功能性质，需你同意。
2. **修代理规则**：你的代理（7897）把 `eastmoney.com` 走了境外节点导致失败；让东财走直连、只有 GitHub/PyPI 走代理，可能两边都通。
3. **等一等再试**：若属临时限流，隔一段时间可能自行恢复。

**请你做的最小验证**：用浏览器打开
`https://push2his.eastmoney.com/api/qt/stock/kline/get?fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56,f57,f58&secid=0.000400&klt=101&fqt=1&beg=20240101&end=20241231`
- 若浏览器能看到一大段 JSON → 说明是 akshare/反爬层面的事，走出路 1；
- 若浏览器也打不开/转圈 → 是链路问题，走出路 2。
