### 3.3 数据源诊断（这部分证据最硬）

装完依赖后报 `RemoteDisconnected`（远端直接断开连接）。我逐层定位，**每一步都有实测**：

| 探测 | 结果 | 说明 |
|---|---|---|
| TCP 连 `push2his.eastmoney.com:443` | 可连 | 网络层没问题 |
| 该主机根路径 `/` | **404** | TLS/HTTP 完全正常，主机活着 |
| 目标接口 `/api/qt/stock/kline/get` | **被远端直接断开** | 问题只在这一个路径 |
| 同路径带浏览器 UA | 同样断开 | 不是 UA 问题 |
| 用 `curl_cffi` 模拟 Chrome TLS 指纹 | 同样断开 | **不是 TLS 指纹问题** |
| 换成 http:// 与加东财 `ut` 令牌 | 同样断开 | 不是协议或参数问题 |
| **另一个**东财接口 `push2.eastmoney.com/api/qt/clist/get` | **HTTP 200，真实数据（1641 只股票）** | 东财整体可用 |
| 经代理 7897 | `ProxyError` | 代理侧也连不上该主机 |

**判定**：不是代码缺陷、不是依赖问题，而是**这台机器到东财历史 K 线接口的链路被中断**。你后来关掉代理后我**立刻重测，错误完全一样**——所以**与代理开关无关**（顺带一提，7897 端口当时其实还在监听）。

**解决**：`services/data_fetcher.py` 改为 **东财 → 新浪 → 腾讯** 三级降级链。实测**新浪源返回 242 行**、**腾讯源返回 242 行**——正好等于历史记录里的 242 个净值点，交叉印证数据正确。

同时按各源差异做了归一化：列名（东财中文 / 新浪腾讯英文）与日期类型（东财字符串 / 新浪腾讯 date 对象）都统一成 `日期/开盘/收盘/最高/最低` 且日期为 `YYYY-MM-DD` 字符串，**与原落库格式完全一致**（首点 `2024-01-02`）。代理锁的语义与依赖缺失的报错信息都保持原样。

**遗留**：分钟级（`1min`/`5min`）**还没接降级链**，仍只有东财一条路，所以目前也不可用。已在代码里注释标明。

## 12. 按「方式②」搁置的模块（不改一行代码，只记录）

你给的两种处理方式里，**方式②**是"放弃这个模块／进程的修改，转而做其它不需要你授权的模块"。以下是本轮**明确判断为"必须由你拍板或目视"因而主动搁置**的模块。它们**全部未改动一行代码**，这里只留下现状、风险与执行路径，供你醒来后决定。

### 12.1 H3：Element Plus 按需化（搁置）

- **现状**：`main.ts` 全局 `app.use(ElementPlus)`、全局注册全部图标、全局引入 `element-plus/dist/index.css`。入口 CSS 实测 **394,294 B**，内有 **3,455** 处 `--el-` 变量。
- **为什么搁置**：这项要逐组件引入样式并删掉全局图标注册，而**删全局图标注册前必须先补齐 9 个图标 import**（`ArrowLeft`、`ArrowRight`、`DataLine`、`Star`、`TrendCharts`、`Trophy`、`Cpu`、`Monitor`、`Loading`）。**漏掉任何一个的表现是图标无声消失——构建和 `vue-tsc` 都不会报错。** 这类静默失败必须由人眼确认，而你在睡觉。
- **另有一个现实障碍**：常规做法要用 `unplugin-vue-components` / `unplugin-auto-import`，它们不在依赖里，安装得走 `npm install`（`AGENTS.md` 明确要求避免，会拖慢你的 IDE）。纯手工版本既繁琐又是高风险。
- **醒来后的执行路径**：见 `docs/4` 批次 2.3。建议你在场时做，做完逐个页面扫一遍图标。
- **🔴 补充（docs/7 §2.40，2026-09-20 深夜）：上面那个「9 个图标」经复核是**对的**，但它**漏了两类同样会静默失效的依赖**，
  而且本项的风险已从"只能目视"降级为"**可机器检查**"：**
  - 依赖全局注册的其实是三类，且**全部只在 TradeSim 的 5 个 `.vue` 里**（门户端 0）：
    **`el-*` 组件 28 种 / 150 处**、**图标 9 个（标签写法）+ 2 个（`:icon="'Back'"`／`:icon="'Refresh'"` 字符串绑定）**、
    **指令 `v-loading` 2 处**；另 `QuestionFilled` 已本地 import，**不**依赖全局注册。
  - **字符串绑定是另一种坑**：`icon` prop 传**字符串**时靠全局注册解析 ⇒ 本地 import 了也**仍然不生效**，必须改写成 `:icon="Back"`。
  - **`v-loading` 是指令不是组件** ⇒ 删掉全局注册后加载遮罩无声消失。
  - **可机器检查的 4 条断言**（详见 docs/7 §2.40 ②）：逐文件核对根模板里的 `el-*`／图标标签是否都在该文件 import 过、
    不残留 `:icon="'…'"`、`v-loading` 要么没有要么指令已注册。加进门禁后，"漏一个变空白"这类风险即可消除，

### 18.5 ⚠ 本轮又一次"我的预期被实测推翻"（第 21 次量具错误）

C2 我第一次写下的预期是「6 根低于下限的 K 线 ⇒ 会建 **6** 次底仓」，而实测旧代码只成交 **2** 次。
**没有把这个 2 当作"问题不严重"就收工**，而是做了对照组：把 `base_position_ratio` 从 0.5 调到 0.2、0.1 ——
旧代码的成交次数变成 **5 次、6 次**（0.1 时正好"每根一次"），新代码在三种比例下**都恰好 1 次**。
⇒ 结论修正为：**旧代码每根跌破下限的 K 线都会再次尝试建底仓，只是受资金约束（每次要花掉初始资金的
`base_position_ratio`）通常只能成交 2 次**。"6 次"的说法是错的，已按实测改写（§16 C2 行、`AGENTS.md`）。
**教训**：观测值低于预期时，先问"是机制不成立，还是被别的约束截住了" —— 这次是后者。
