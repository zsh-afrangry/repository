`docs/4` 只判断出第 1 层。真实情况是 **`desheng` 环境同时缺 `akshare` 和 `pyarrow`**。而 `backend/requirements.txt:9-12` **本来就正确声明了** `polars / pandas / pyarrow / akshare`——所以这不是文档错误，**是这个 conda 环境从未按 requirements 装全**。`docs/2` 说"缺 polars"是错的（polars 1.44.0 一直在）。

- Python 3.13.11 上安装与导入都正常，**先前担心的 3.13 兼容性问题没有发生**

### 3.3 数据源诊断（这部分证据最硬）

装完依赖后报 `RemoteDisconnected`（远端直接断开连接）。我逐层定位，**每一步都有实测**：

| 探测 | 结果 | 说明 |
|---|---|---|
| TCP 连 `push2his.eastmoney.com:443` | 可连 | 网络层没问题 |
| 该主机根路径 `/` | **404** | TLS/HTTP 完全正常，主机活着 |
| 目标接口 `/api/qt/stock/kline/get` | **被远端直接断开** | 问题只在这一个路径 |
| 同路径带浏览器 UA | 同样断开 | 不是 UA 问题 |
| 用 `curl_cffi` 模拟 Chrome TLS 指纹 | 同样断开 | **不是 TLS 指纹问题** |
| 换成 http:// 与加东财 `ut` 令牌 | 同样断开 | 不是协议或参数问题 |
| **另一个**东财接口 `push2.eastmoney.com/api/qt/clist/get` | **HTTP 200，真实数据（1641 只股票）** | 东财整体可用 |
| 经代理 7897 | `ProxyError` | 代理侧也连不上该主机 |

**判定**：不是代码缺陷、不是依赖问题，而是**这台机器到东财历史 K 线接口的链路被中断**。你后来关掉代理后我**立刻重测，错误完全一样**——所以**与代理开关无关**（顺带一提，7897 端口当时其实还在监听）。

**解决**：`services/data_fetcher.py` 改为 **东财 → 新浪 → 腾讯** 三级降级链。实测**新浪源返回 242 行**、**腾讯源返回 242 行**——正好等于历史记录里的 242 个净值点，交叉印证数据正确。

同时按各源差异做了归一化：列名（东财中文 / 新浪腾讯英文）与日期类型（东财字符串 / 新浪腾讯 date 对象）都统一成 `日期/开盘/收盘/最高/最低` 且日期为 `YYYY-MM-DD` 字符串，**与原落库格式完全一致**（首点 `2024-01-02`）。代理锁的语义与依赖缺失的报错信息都保持原样。

**遗留**：分钟级（`1min`/`5min`）**还没接降级链**，仍只有东财一条路，所以目前也不可用。已在代码里注释标明。
