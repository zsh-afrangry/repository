## 已修复的行为

- 首页搜索/状态筛选使用 `v-show` 保留原卡片节点，恢复时不丢滚动揭示观察关系（D8）；空结果有提示。项目卡片支持键盘进入，现有列表视图选择器实际切换为单列。
- 首页首屏去掉超出常见桌面宽度的固定最小列宽；组件行高随内容增长。窄屏导航/筛选换行，天气/进度布局随宽度适配，避免被外层 overflow 裁掉。
- 日历“查看全部”明确打开今天，避免没有 activeDate 时弹窗无日期、无法新增；保留已有新增/删除能力，没有扩展编辑功能。切月只接收最新请求结果。
- 账单 PATCH 的 record_type、expense_date、amount、reimbursement_status 不接受显式 null，HTTP 返回422；省略字段不修改，可空字段仍允许清空（D5）。
- 账单编辑保留有效小类；更换到不匹配的大类才清空小类。日分组折叠使用响应式集合。
- 月列表取完分页，不再静默截断到200条；后端以 id 为第三排序键，避免同日同时记录的分页次序不稳定。
- 账单列表与汇总成对加载，只接收最新月份结果；失败时隐藏汇总，不再展示旧金额或把错误称为“暂无记录”。提供重试，标签失败单独显示且禁止不完整表单编辑。
- 新建/修改后切到记录所属月份；重复提交有守卫，写入期间表单禁用，错误留在弹窗中。接口422错误数组转为可读字段错误。
- 账单/日历弹窗补 Escape、Tab焦点约束、关闭后焦点返回与滚动锁；账单表单标签关联控件，窄屏行操作可见，日期/时间纵排避免原生日期输入裁切。

## 首页天气地点可切换（2026-10-06）

首页天气板块的地点过去写死在**四个**位置，用户无法修改：`routers/weather.py` 里的 QWeather Location ID、经纬度、展示名 `广东省 · 广州市 · 天河区`，以及 `Dashboard.vue` 占位对象里的同一个字符串。现在点击 📍 展开选择器，可选常用城市或按关键词搜索。

| 落点 | 内容 |
|---|---|
| `frontend/src/components/ui/WeatherLocationPicker.vue` | 选择器本身：预设城市 + 去抖搜索、↑↓/Enter/Esc 键盘操作、点击外部关闭。只负责"选出 Location ID"，不取天气、不碰存储 |
| `frontend/src/api/weather.ts` | `current(locationId?)` 与 `searchLocations(q)` |
| `frontend/src/types/portal.ts` | `WeatherInfo.locationId`、`WeatherLocation` |
| `frontend/src/views/Dashboard.vue` | 接线；选择持久化在 `localStorage` 的 `km.weather.locationId`，后端解析失败时不把坏值写回 |
| `backend/app/routers/weather.py` | `GET /weather/?location=<Location ID>`（省略用默认城市）与 `GET /weather/locations?q=` |

三个「为什么这么做」的结论，改动前请先读：

- **换城市必须走 GeoAPI，因为空气质量接口用经纬度。** `/v7/weather/*` 收 Location ID，但 `/airquality/v1/current/` 收 `lat/lon`，所以只换 ID 不够，得先用 `/geo/v2/city/lookup` 一次拿到 `id` + `lat` + `lon`。GeoAPI 失败时 `_resolve_place()` 返回 `None`，天气照常加载、空气质量退回按 Location ID 请求，展示名降级为 ID 本身。
- **原来的缓存是单槽的，这本身就是缺陷。** 旧的 `_cache = {"expires_at", "value"}` 只存一条，换城市再换回来会在 TTL 内拿到上一个城市的数据。现在 `_weather_cache` 按 Location ID 分槽，搜索另有 24 小时 `_geo_cache`（`/weather/locations` 每个新关键词消耗一次 GeoAPI 调用，预设城市不消耗）。
- **标签要按行政区划后缀去重。** `adm1 · adm2 · name` 直接拼会让城市级结果变成「四川省 · 成都市 · 成都」；`_skeleton()` 先去掉省/市/区/县再比较，同地两级只保留一级。

同轮修复的显示问题：地点切换后页面可能整体横向错位、刷新即恢复。成因是页面缺少横向溢出兜底，而 `overflow-x: hidden` 的元素仍可被程序化横向滚动，`focus()` 默认的 `scrollIntoView` 会在横向留下偏移。现在三处一起收紧：触发按钮与容器补 `min-width: 0`、`focus({ preventScroll: true })`、`html/body` 加 `overflow-x: hidden`。修复范围与边界见下方「验证与复跑」第 4 条。

同时删除的冗余图层（同一轮）：`Bills.vue` 的 `.starry-workspace` 背景被 fixed 星空画布完全遮挡、恒不可见；`App.vue` 根容器的 `bg-surface` 与 `index.html` 的 body 底色同为 `#0f0f14`。两处删除经 CSS 级联快照比对为零变化。

## 冗余图层清理与 Vault 去重核查（2026-10-06）

删除了两处确定不可见的图层，均经 CSS 级联快照比对确认为零变化（改前改后每个 (文件, 作用域, 选择器, 属性) 的最终生效值逐条相同）：

- `Bills.vue` 的 `.starry-workspace` 背景 `rgba(7, 8, 22, 0.78)`。星空画布是 `position: fixed; inset: 0`、尺寸取 `window.innerWidth/innerHeight`、底色 `#070816` 完全不透明，覆盖范围恒等于视口，因此这一层在任何时刻都不可能被看到。`position`/`isolation` 保留——它们负责把 fixed 画布困在本页层叠上下文里，是功能性的。
- `App.vue` 根容器的 `bg-surface`。它与 `index.html` 的 `<body class="bg-[#0f0f14]">` 同为 `#0f0f14`，属重复页面底色；body 的底色被保留，因为它是 Dashboard/Notes 等透明页面唯一的兜底底色。

**Vault 去重核查结论：文件内无重复可合并。** 曾有一次审计称 Vault 有 39 条可删声明，那是把 Dashboard 与 Vault 的**同名 scoped 类**当成跨文件重复了——Vue 的 scoped 样式是互不影响的独立级联上下文，同名类不是重复定义。四重核对均为零：同规则块内重复属性 0、同选择器文件内重复定义 0、与 `main.css` 共同定义的选择器 0、模板用到的类全部有定义。

**但跨文件重复确实存在，尚未处理。** Vault 与 Dashboard 有 9 组规则逐值完全相同：`.section-block`、`.section-heading`、`.section-heading span`、`.section-heading h2`（含 `.about-content h2`、`.newsletter-inner h2`）、`.outline-button`，以及 `.tone-cyan/violet/emerald/amber` 四个色值类，合计约 55 行。提取到共享样式表本是纯搬运、零视觉风险，但 AGENTS.md「储物间」一节明确要求"不要在没同步更新 Dashboard scoped 样式的条件下把它们去重"，且这类重构需要浏览器视觉验收——本机 Chrome 受沙箱限制无法启动，故留待有浏览器环境时处理。
