## 1. 目标与已确认要求

Notes 从以 Transformer 为默认入口的页面，调整为个人学习笔记、学习路线与记录的模块。内容具有三个层次：

```text
主题：Transformer / 数据库 / CNN / 机器学习与神经网络 / ViT / 算法 / …
  └─ 目录分区（小知识点）：输入层 / 注意力机制 / 编码器 / …
       └─ 知识单元：QKV / 缩放点积注意力 / 多头注意力 / …
```

学习总览是模块入口，不增加第四层内容归属。

| 用户已确认 | 开发要求 |
|---|---|
| 新增学习总览，可进入各主题 | Transformer 成为其中一个主题，不再代表整个 Notes |
| 每个主题拥有自己的工作区 | 标题、目录、单元和布局参数随主题变化，不固定四列 |
| 学习依赖是两个知识单元之间的关系 | 新增、编辑单元时提供前节点和后节点选择；允许多选与明确无依赖 |
| 目录归属是单元固有属性 | 创建时指定，编辑时可调整；与依赖关系分别维护 |
| 接受主题工作区布局 | 顶部上下文导航，左侧目录，中央目录/学习路线切换，进入单元阅读 |
| 重新分析 Notes 系列统一背景 | 在现有视觉基础上判断保留、减弱、移除和补充，不先叠加特效 |
| 通用样式可拆装，模块保留特色 | 使用装饰者模式的组合思路，构建基础组件、可选装饰和模块样式 |

“学习记录”的具体字段、完成状态和复习规则尚未定义；本方案不自行加入打卡、掌握率、进度百分比或学习时长统计。

## 2. 当前代码基线与问题

核查入口：[Notes.vue](../frontend/src/views/Notes.vue)、[main.ts](../frontend/src/main.ts)、[main.css](../frontend/src/styles/main.css)、[Dashboard.vue](../frontend/src/views/Dashboard.vue)。以下描述为本次方案建立时的现状，不代表改造后行为。

### 2.1 功能基线

- `/notes` 当前重定向到 `/Transformer`；Transformer、Database、CNN、MachineLearning 四个路由共用 Notes.vue。已有四个主题配置，尚无独立学习总览；ViT、算法还需新增。
- `NotebookConfig.columns` 是四元素元组，图谱坐标、SVG 范围与分隔背景也含四列假设。仅修改数组类型不足以完成动态布局。
- 单元通过数字 `stage` 表示目录位置，通过 `prerequisites` 表示前置单元；后置关系可从前置关系反向推导。
- 新建单元及改变阶段时，代码会自动将前一阶段全部单元设为前置依赖。该推断不能表达用户指定的真实学习关系，实施时必须替换。
- 阅读器目前依赖组件状态打开，缺少知识单元的独立深链接。新建、编辑、删除和导入只改变内存，刷新或离开后不能可靠保留。
- Markdown、公式显示和导入仍有独立遗留，见 P9–P11；更换布局不等于这些能力已经完善。

### 2.2 视觉基线

Notes 使用页面自己的 `--reference-*` 配色、渐变背景与圆环装饰，未复用首页的背景组件。工作区外层、图谱容器和 SVG 存在重复底色；同一选择器也有后置覆盖。当前生效的 Notes 顶部 `backdrop-filter` 为 `none`，不能依据早期声明称它仍在多重模糊。

阅读器是全屏覆盖层，背景包含网格；内部主要内容容器透明，不能将每一层 DOM 都当成独立的不透明图层。首页则已有固定渐变背景、Hero 光晕和局部粒子 Canvas，以及卡片玻璃/悬停装饰，装饰职责也值得梳理。

这些证据说明风格和装饰归属需要收口，**并不等于已经证明 GPU 合成层过多或存在性能故障**。重复 CSS、DOM 层级、绘制背景和浏览器合成层应分别检查。首页/账单此前的功能验收也不代表已完成全站样式重构。

## 3. 功能设计

### 3.1 页面、导航与功能展示

以下 URL 是建议采用的工程方案，实施时同步路由与旧链接兼容。

| 页面 | 建议路由 | 主要展示与操作 |
|---|---|---|
| 学习总览 | `/notes` | 主题列表/卡片、简介、按实际数据计算的目录与单元数量、主题搜索、进入工作区 |
| 主题工作区 | `/notes/:topicId` | 主题介绍、目录树、主题内搜索、目录/学习路线切换、新建单元 |
| 知识单元阅读 | `/notes/:topicId/units/:unitId` | 正文、目录归属、前后依赖入口、编辑、返回工作区 |

总览提供 Transformer、数据库、CNN、机器学习与神经网络、ViT、算法等主题入口；没有正文的主题显示空状态，不编造完成数量或填充学习内容。主题和目录已提供创建、改名、排序与受保护删除界面；新主题无需修改代码。

主题工作区采用紧凑顶部介绍，首屏能看到目录与单元。左侧为目录和单元树，中央默认提供目录视图，也可切换学习路线图；二者读取同一组数据。选中单元后可看到摘要、归属与关系，并进入阅读器。搜索无结果与主题无内容使用不同提示。

窄屏将目录树收起为可访问的目录面板；中央优先展示可阅读列表。图谱可局部平移/滚动，不用缩小整个页面来容纳全部列。

阅读器展示“学习笔记 / Transformer / 注意力机制 / QKV”上下文。返回工作区应恢复该主题的目录选择、筛选、视图与滚动；浏览器前进/后退应与阅读路径一致。目录无需强制再建一层路由，可通过查询参数表达选中目录和视图；深链接需要恢复的状态进 URL，临时悬停等状态留在组件内。

旧 `/Transformer`、`/Database`、`/CNN`、`/MachineLearning` 重定向到对应主题；门户的 Notes 通用入口改到总览，明确指向某主题的链接仍可直达该主题。未知主题或单元应给出明确不存在提示，不默默落到 Transformer。

### 3.2 数据模型：归属与依赖独立

建议使用稳定 ID，目录改名和排序不影响单元归属；以下是概念契约，不是已落地 API 或数据库表。

```ts
interface Topic {
  id: string
  title: string
  description: string
  sections: Section[]
  workspace?: { preferredColumns?: number }
}
interface Section { id: string; title: string; order: number }
interface KnowledgeUnit {
  id: string
  topicId: string
  sectionId: string
  title: string
  content: string
  tags: string[]
}
interface DependencyEdge {
  fromUnitId: string // 被依赖的前节点
  toUnitId: string   // 依赖它的后节点
}
```

单元 ID 应全局唯一；若迁移时保留主题内旧 ID，关系引用必须包含 topicId，不能依赖不同主题碰巧没有同名单元。单元的 sectionId 必须属于它的 topicId。调整目录归属只改变归属字段，不重新生成依赖。

建议关系只存一份规范化边集合，界面从它派生前节点和后节点：`A → B` 表示 B 依赖 A。编辑 N 时，选择前节点 P 创建 `P → N`，选择后节点 S 创建 `N → S`；取消选中移除对应边，其他不相关边不受影响。图谱、阅读器、编辑器共享此契约，不各存一套关系。

新建/编辑表单包括标题、目录归属、正文、标签、前节点多选、后节点多选。用户需能明确选择“无前置依赖”或“无后续依赖”，根节点与终点合法，不强制两侧都有节点。禁止自依赖、重复边和不存在的引用；关系变更作为一次操作校验和提交，不能只成功更新一侧。

跨主题依赖、循环依赖和删除策略已由用户确认，见第 6 节。当前示范关系可作为迁移资料，但不能把自动推断的关系标成已确认的专业知识结论；也不能未经检查一次性清空旧关系。

### 3.3 可变列数与配置组织

**不建立包含所有参数的单一总配置文件。** 按职责组织：

| 配置/数据 | 建议归属 | 约束 |
|---|---|---|
| 主题、目录、简介和初始单元 | `features/notes/data/` | 属于内容数据，后续可由存储层提供 |
| 布局默认值与图谱间距 | `features/notes/config/workspace.ts` | 类型化默认值，可被主题配置覆盖 |
| 主题布局偏好 | `Topic.workspace` | 可选；使用默认值时无需每个主题重复填写 |
| 全站颜色、间距、圆角、边框等语义令牌 | 现有 `styles/main.css` | 复用并补齐现有体系，避免另一套同义令牌 |
| Notes 特有颜色/图谱样式 | Notes 容器与组件 scoped 样式 | 通过 CSS 变量局部覆盖，不能外泄 |
| 选择、搜索、滚动等运行状态 | Notes composables/状态容器 | 不写入静态配置文件 |

目录数量由 `sections.length` 决定，不再另存一个必须手动同步的目录数。`preferredColumns` 控制卡片布局偏好，实际可见列数还受容器宽度和最小卡片宽度约束；它不改变知识目录数量。

学习路线图若按目录分列，逻辑列数来自目录数据，坐标和 SVG 范围动态计算。分隔线、空目录、跨列连线、增删排序都使用同一布局结果；不再保留四列硬编码。若内容过宽，采用局部滚动或明确的缩放操作。

### 3.4 模块拆分与存储边界

将 Notes 的数据类型、内容、布局计算、关系处理和界面拆到 `frontend/src/features/notes/`，views 只承担页面入口。建议按实际职责逐步形成总览、工作区、目录树、路线图、阅读器和单元编辑器组件，避免一次性设计大量没有消费者的空抽象。

页面通过独立的数据访问接口读写，为 P9 持久化留出替换位置。选择存储方案前不能把内存保存称为长期保存；开发中的内存模式必须明确显示边界。若采用后端，Notes 后端按 feature module 组织，使用现有共享数据库设施；请求经前端 API 层，不在页面直接 fetch。

P9 已采用现有 MySQL 落地（第 11 节）；正文、结构和依赖一起保存。备份依靠数据库备份，冲突失败保留草稿并提供草稿 JSON 导出，不提供自动备份或完整主题导入恢复界面。P10 公式排版、P11 导入修复另行跟踪，不因本方案自动扩大到完整笔记编辑器。

## 4. 视觉与可组合样式设计

### 4.1 先决定背景职责，再实施抽取

对总览、工作区、阅读器与首页建立相同尺寸的截图和生效样式基线，登记每个背景、边框、阴影、模糊、网格与动画的拥有者、用途和关闭方式。检查实际渲染，不按 CSS 声明数量判断图层开销。

建议统一 Notes 系列的基础底色、文字对比度和控件语言；总览可保留轻量主题氛围，工作区减少干扰，阅读器优先正文可读性。图谱网格可选，正文背景网格优先尝试移除。用保留/减弱/移除的对照结果确定最终视觉值，不把“增加一层渐变”当统一风格的默认手段。

每一层只承担明确职责：页面底色 → 可选背景装饰 → 内容表面 → 必要浮层。重复同色填充可合并，但图谱裁剪、浮层遮罩、焦点反馈等有功能的层应保留。首页和账单作为一致性参照与回归对象；本阶段不自动重做它们的视觉，也不触碰 TradeSim。

### 4.2 装饰者模式在 Vue 中的落地

采用“基础组件 + 可选装饰 + 模块样式”的组合，利用 slots、少量语义 props 与 CSS 变量实现。无需建立类继承框架，也不让每种装饰都增加一层 DOM。

| 层次 | 候选构件 | 职责 |
|---|---|---|
| 语义令牌 | 表面、文字、边框、焦点、间距、圆角、动效 | 统一视觉基础与可访问性 |
| 基础组件 | Button、Surface、PageHeader、EmptyState | 控件语义、布局、交互状态；名称实施时按现有组件调整 |
| 可选装饰 | 微弱光晕、边缘高亮、玻璃表面、图谱网格 | 提供单一效果，按需挂载或启用 |
| Notes 独有样式 | 目录树、知识节点、依赖连线、阅读排版 | 服务领域内容，局部消费共享令牌 |

示意组合（不是已存在的组件 API）：

```vue
<NotesPageShell>
  <template #background><SubtleGlow /></template>
  <Surface variant="workspace">
    <template #decoration><GraphGrid v-if="showGrid" /></template>
    <KnowledgeGraph />
  </Surface>
</NotesPageShell>
```

简单边框/光晕用组件 variant、类或伪元素即可；独立背景、Canvas 或具有生命周期的效果才考虑独立组件。移除 decoration 后，内容布局、点击、键盘操作和文字对比度仍成立。避免全功能“大组件”和互相依赖的大量布尔开关。

具体约束：

- 背景组件只渲染自己，不设置消费者的布局、字体、配色或滚动。装饰默认不截获指针，不参与键盘焦点，纯装饰对辅助技术隐藏。
- 交互状态由基础控件负责：默认、悬停、按下、焦点、禁用、加载和错误；模块只覆盖允许的视觉变量，不能移除可见焦点。
- 同一个效果只由一个位置负责；页面背景、表面样式和模块节点不重复叠加相同模糊或光晕。动画组件负责自身启动、降级和卸载清理。
- scoped 样式保持隔离，不新增非 scoped Vue 样式块或 `:global()`；全局令牌延续现有主样式入口。保留既有浅色主题代码边界。
- 先从实际重复处提取已使用的公共能力，Notes 特有部分保留本地。抽取影响首页/账单时，以已有流程和截图回归证明没有意外变化。
- 整理重复声明时确认最终生效值，将规则收拢到明确位置，不继续在文件尾部增加覆盖补丁。动效遵循 reduced-motion，并处理切换、卸载和尺寸变化。

## 5. 建议实施顺序与验收

以下是依赖顺序，不是第二份执行状态表。P12、P13、E8 的进度只在根清单维护。

| 阶段 | 产出 | 验收重点 |
|---|---|---|
| 基线与契约（P12/P13/E8） | 截图、主题/目录/单元契约、配置边界、关系操作规则、视觉职责表 | 区分现有行为与目标；记录仍待决定的产品规则 |
| 总览与路由（P12） | 总览、主题入口、旧路由兼容、空状态 | 所有主题可进入；未知路径可解释；入口不再默认 Transformer |
| 工作区与阅读（P12） | 动态布局、目录/路线切换、单元深链接、状态恢复 | 1/3/4/6 个目录、空目录、长标题；320/390/768/1440 宽度；前后退与刷新 |
| 归属与关系（P13） | 显式前后节点编辑、归属字段、统一关系数据 | A→B 两侧一致；移除与多选正确；移动目录不改边；异常引用不提交 |
| 视觉组件化（E8，与上述界面实施协同） | 基础样式、可选装饰、Notes 专有样式、旧覆盖规则清理 | 装饰逐项关闭仍可使用；鼠标/键盘/减少动效可用；主题切换无样式泄漏 |
| 持久化及联调（P9，先确定方案） | 长期保存与恢复、写入错误反馈 | 新建/修改/关系经刷新及离开后仍一致；失败不能伪装成功 |

源数据迁移需建立旧数字 stage 与新 sectionId 的映射，保留标题、正文、标签和可核查关系。路由迁移与内容 ID 迁移分别验证，不因改 URL 丢失内容。导入/编辑中的未保存修改应有离开保护；删除影响和恢复方案确定后再落实操作。

验证包括必要的数据与关系行为测试、前端类型检查/构建，以及真实浏览器的布局、导航、键盘和视觉检查。构建通过不能替代页面验收；没有性能测量时不声称减少了多少 GPU 图层或提升了多少性能。实施完成后按实际改动同步 [效果登记册](1_前端界面背景与特效整理.txt) 和验收证据。

## 6. 用户最终确认的产品规则

用户已明确“全部按建议，继续完成文档13的上述范围，直至可验收”。以下替代方案阶段的待定项：

| 项目 | 已确认并采用 |
|---|---|
| 持久化 | 现有 MySQL + 后端 API，保存 Markdown 正文、主题、目录和依赖 |
| 依赖范围 | 仅同主题；禁止自依赖、重复边、无效引用及循环；循环错误指出一条冲突路径 |
| 删除单元 | 确认时提示关联边数量；删除单元及其关联边，保留其他单元 |
| 删除目录/主题 | 非空时拒绝直接删除；先明确迁移或单独删除内容，再移除空容器，不提供隐式级联删除 |
| 主题和目录管理 | 界面支持创建、改名、排序；主题提供布局列数设置 |

## 11. 现行实现与数据契约

### 11.1 入口与模块边界

- `/notes` 为学习总览；`/notes/:topicId` 为主题工作区；`/notes/:topicId/units/:unitId` 为单元深链接。原四个专题 URL 保留重定向，门户通用 Notes 入口已改为总览。
- 工作区紧凑标题、主题切换、左侧目录树、搜索与目录/路线视图；窄屏目录为有界滚动区域，图谱独立横向滚动，不撑宽整页。主题偏好列数 1–6，卡片布局按可用宽度降级；路线图按实际目录数布局。
- URL 查询参数 `q/section/view/selected` 保存搜索、目录、视图与选择；页面内导航记忆保存滚动和焦点。阅读器有焦点约束、Esc 关闭、关闭后焦点恢复及背景 inert；未保存修改有离开确认和 beforeunload 提示。
- `views/Notes.vue` 负责页面组合；`features/notes/composables/useNotesWorkspace.ts` 管 API 状态和草稿；`NotesGraph/NotesDialog/NotesProse` 分管图谱、浮层和正文。API 位于 `api/notes.ts`，后台在 `app/notes/`，不扩散到门户按层业务目录。
- 通用 Surface/Button/Glow/Grid 与模块 scoped theme 延续前四批设计。无新依赖、全局样式或持续动画；移除了旧巨型页面中不再参与新界面的四列布局和旧侧抽屉样式。全站亮色主题仍保留，TradeSim 未修改。

### 11.2 MySQL 保存与初始化

共享原 `Base/engine/SessionLocal/get_db`，新增 `notes_topics`、`notes_seed_versions` 两张表；启动时 create_all 仅创建新表，不修改原业务表。

`notes_topics` 每行保存一个主题聚合：稳定 id、整数 version、JSON data。data 包含主题字段、sections、units、edges；每个单元有稳定 sectionId。使用一个聚合是本阶段的明确选择：同主题依赖没有跨主题外键需求，所有正文/目录/关系可一次验证并原子提交，避免多张表写到一半。不是新建第二套数据库设施；大量跨主题查询需求出现后再评估规范化拆表。

接口：

```text
GET    /api/notes/topics                    总览摘要与真实数量
POST   /api/notes/topics                    创建主题
GET    /api/notes/topics/{topic_id}          完整主题
PUT    /api/notes/topics/{topic_id}          携带 version，原子替换聚合
DELETE /api/notes/topics/{topic_id}?version=...  仅允许空主题
```

PUT/DELETE 使用 id + version 条件写入，成功后版本递增；过期写入返回 409。服务端验证目录归属、边端点、重复边、自依赖和 DAG；失败不产生部分写入。客户端保存期间禁止重复提交，失败保留草稿，读取失败提供重试，不用内存样例冒充已保存内容。

标识命名空间为 `(topicId, unitId)`，边在所属主题聚合内解析；不把其他主题的同名单元误当合法引用。新 ID 使用 UUID，迁移单元保留原 ID，旧数字 stage 映射到稳定 sectionId。主题最多 200 个目录、2000 个单元、20000 条边；每单元正文最多 1000000 字符，主题正文总量不超过 5MB（UTF-8），超限明确拒绝。

`seed.json` 保留四主题的 27 个现有单元，另将未归入旧四主题的 4 篇原文放入“迁移保留笔记”；共 31 个单元。ViT 和算法为空主题，不虚构正文。所有迁移例子提示关系需自行核对。初始化标记 `legacy-v1` 保证后续启动不重置用户内容，已删除的初始主题不会重新出现。此数量是本轮初始化快照，不是永久业务断言。

备份应覆盖两张 Notes 表及其字符集，不可只备份正文而遗漏目录、依赖或初始化标记；恢复到生产库属于单独运维操作，本轮未演练灾备恢复。冲突时先保留/导出草稿，再重新载入比较，不提供静默覆盖和自动合并。

### 11.3 Markdown 与数据操作边界

采用已安装的 marked 进行块结构解析，再经已安装的 DOMPurify 清理 HTML。列表/强调/代码块顺序不再由脆弱正则决定；代码块与表格有可聚焦的局部滚动容器。数学公式仅保留普通 Markdown 文本语义，不声称支持 LaTeX 排版。

导入为单个不超过 1MB 的 `.md` 文件，先进入草稿，用户确认保存后才落库。支持有/无 Frontmatter；支持 title 和行内 tags 数组，移除已解析元数据块；未知 YAML 格式明确报错并保留原文件，不静默丢字段。完整 YAML、多文件导入和编辑器语法高亮不属于本轮。
