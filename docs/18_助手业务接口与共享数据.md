## 范围与业务规则

KnowledgeMap 保存唯一的账单和待做数据。网站和 Fusion 助手通过业务接口使用同一行；不复制待办/账本做双向同步。第一轮天气、待做维护、账单新增/查询/月汇总；账单修改/删除第二轮，默认天气城市共库后续迭代；Notes 和 TradeSim 不接入。

待做逾期不自动作废；完成、作废独立且可恢复。`event_date=NULL,event_time=NULL` 表示无 DDL/未安排，不能过期，不计入日历周进度；日期已知、时刻为空仍表示当日结束。保留旧日期项的含义，不猜测其来源。新增 `note` 保留备注，`version` 用于网页和助手并发校验。无日期项在待做列表可见，不放入某个虚构的日历格。

## 接口契约

助手接口位于 `/api/assistant/`，专用 Bearer token 从 `KM_ASSISTANT_TOKEN_FILE` 读取（默认用户私密 `.config/knowledgemap/assistant-token`）；未配置时拒绝，不能复用网站登录凭据。固定接口只开放三个纳入领域，不提供通用 SQL/URL。

写请求带 `Idempotency-Key` 与可选 `X-Kurumi-Run-Id`。同键同参返回原结果，不同参数拒绝；业务行与请求账本同事务提交。待做维护使用真实 ID 和 `expected_version`；网站现有接口也接受版本，ORM 检测并发写。出现未知写入结果可用同键同参重试，不生成新键重复记账。

## 迁移与恢复

定向迁移只添加列、调整可空日期并创建助手请求/来源映射表，不运行 `knowledgemap.sql` 整库快照。执行前做一致性备份。旧助手 `expired` 导入为已作废并保留来源状态，不自动恢复；原文与字段保存在来源资料中，重复导入不重复建行；冲突先预览并停止该分支。

版本化全库结构快照已从真实库重新导出。账单/标签原快照的注释与TradeSim索引名等历史差异也随导出对齐；与今晚变更前SQL备份比较，这些表的结构逐字一致，本轮没有ALTER它们。真实升级仅执行定向迁移，不执行全库快照。

## 运行与恢复

专用服务 `knowledgemap-assistant.service` 仅监听 `127.0.0.1:3086`，默认token文件 `~/.config/knowledgemap/assistant-token`（600），不依赖开发端口3085或网站8020登录，不随 `dev-stop` 停止。环境来自同一个 `backend/.env`；不复制数据库凭据到Fusion。安装模板后 `systemctl --user daemon-reload`、`enable --now knowledgemap-assistant.service`。业务DDL须先执行，服务本身不自动ALTER或导入。

写入超时不能当失败后另记一笔：使用原可信消息生成的同一幂等键与相同参数核对。分页快照包含整份事项列表的ID/version，分页期间变化返回409。月汇总对助手用十进制字符串，网站原数字契约保持不变。

结构升级为添加note/version、日期可空、增加请求与来源表；不DROP现有业务表。迁移后停用桥接可保留这些兼容列。涉及真实数据回退，先停桥接写入，保存切换后的新记录，不能用今晚备份直接覆盖新事实。具体切换与Fusion固定runner保护见跨项目文档23。

### 定期备份

`python backend/scripts/backup_assistant.py --output-dir <新的绝对目录>` 读取同一backend/.env，用临时0600客户端文件调用mysqldump，导出压缩SQL和专用私密配置，SHA256针对gzip字节。失败标记存在即不能恢复；不把它称为Fusion完整快照。与Fusion备份配对时记录各自路径/时间，跨系统一致停写需要另安排，不能将两份分时快照误称同一时刻。
