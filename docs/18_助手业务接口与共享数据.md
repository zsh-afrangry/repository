## 范围与业务规则

KnowledgeMap 保存唯一的账单和待做数据。网站和 Fusion 助手通过业务接口使用同一行；不复制待办/账本做双向同步。当前提供天气、待做维护、账单新增/查询/月汇总及单笔修改/实际删除。网页跟随助手所在地已部署，规则见 Fusion 文档23。Notes 和 TradeSim 不接入。

待做逾期不自动作废；完成、作废独立且可恢复。`event_date=NULL,event_time=NULL` 表示无 DDL/未安排，不能过期，不计入日历周进度；日期已知、时刻为空仍表示当日结束。保留旧日期项的含义，不猜测其来源。新增 `note` 保留备注，`version` 用于网页和助手并发校验。无日期项在待做列表可见，不放入某个虚构的日历格。

## 接口契约

助手接口位于 `/api/assistant/`，专用 Bearer token 从 `KM_ASSISTANT_TOKEN_FILE` 读取（默认用户私密 `.config/knowledgemap/assistant-token`）；未配置时拒绝，不能复用网站登录凭据。固定接口只开放三个纳入领域，不提供通用 SQL/URL。

写请求带 `Idempotency-Key` 与可选 `X-Kurumi-Run-Id`。同键同参返回原结果，不同参数拒绝；业务行与请求账本同事务提交。待做维护使用真实 ID 和 `expected_version`；网站现有接口也接受版本，ORM 检测并发写。出现未知写入结果可用同键同参重试，不生成新键重复记账。

账单组导入使用 `/api/assistant/bills/import/group/preview`、`group/commit` 与只读 `group/receipt`。预览按文件顺序模拟来源去重及标签创建。提交携带预览指纹，重算不符时整组拒绝。具有新增记录的文件分别登记批次，整组与请求回执同事务提交。丢失响应时按原幂等键查组回执。复用现有账单批次与来源表。

## 迁移与恢复

定向迁移只添加列、调整可空日期并创建助手请求/来源映射表，不运行 `knowledgemap.sql` 整库快照。执行前做一致性备份。旧助手 `expired` 导入为已作废并保留来源状态，不自动恢复；原文与字段保存在来源资料中，重复导入不重复建行；冲突先预览并停止该分支。

版本化全库结构快照已从真实库重新导出。第一轮没有ALTER账单/标签；第二轮仅给bills添加version，原三表业务行哈希不变。真实升级仅执行定向迁移，不执行含DROP的全库快照。

## 第二轮账单维护与验证

2026-10-17用户授权完整账单增删改查，并确认明确且唯一的单笔修改/实际删除直接执行，有歧义先澄清，不批量、不增加回收站或自动撤销。以下为已部署的第二轮契约。

- `Bill.version` 是两入口共享的乐观版本；读账单含version，网页PATCH带expected_version，DELETE以查询参数传expected_version；不带版本拒绝。ORM最终UPDATE/DELETE也校验版本，覆盖查询与写入间的并发。
- `GET /api/assistant/bills` 支持id精确查询和query备注/流水号字面筛选；保留日期/分类分页与月汇总。
- `POST /api/assistant/bills/manage` 接收action=update|delete、id、expected_version；update.fields只接受实际业务字段，省略保持、可空值可显式清空；delete不接受fields。单条新增和维护共用可信消息的账单幂等键，写入与回执同事务。
- 维护回执保存before快照及item结果，删除后同键重试返回原结果，不二次执行。快照在私密共享数据库中，不进入日志或Git。版本冲突重新查询。
- `GET /api/assistant/bills/receipt` 按原消息的 `Idempotency-Key` 只读查询已提交的账单回执。返回动作、账单 ID、原结果版本、金额和账单日，删除时返回删除标记。缺少回执返回 `bill_receipt_not_found`，调用方保留结果未知。接口使用既有助手鉴权和请求表。
- 定向DDL仅给bills加version，留档`backend/sql/assistant_bills.sql`；沿用migrate_assistant.py和变更前MySQL备份，不执行全库结构快照。
- 网站仅更新版本字段和必要的API传参，账单视觉重构属于独立P15。
