## 1. 统一命名与计数口径

### 1.1 背景和表面

| 名称 | 定义 | 是否计入全局背景层 |
| --- | --- | --- |
| `BG_BASE_DARK` | 页面或路由的深色基础底色，通常是一层线性渐变或纯色 | 是 |
| `BG_GLOW_GLOBAL` | 覆盖整个页面的静态径向渐变光晕 | 是 |
| `BG_GLOW_SECTION` | 只属于某个 Hero、区块或路由的静态渐变光晕 | 是，单独计数 |
| `BG_PARTICLE_AUTO` | 不依赖鼠标、自动持续运行的粒子、星点和连线 Canvas | 是，按一个动画层计数 |
| `SURFACE_GLASS` | 内容卡片自己的半透明填充、边框、阴影和模糊 | 否，属于内容表面 |
| `SURFACE_GLOW_LOCAL` | 卡片或组件内部的固定装饰光晕 | 否，属于局部表面 |

### 1.2 鼠标和悬停效果

| 名称 | 定义 | 典型实际效果 |
| --- | --- | --- |
| `FX_CURSOR_SPOTLIGHT` | 光晕中心跟随鼠标在目标元素内部的位置 | 项目卡片内部出现径向光晕 |
| `FX_CURSOR_PARTICLE` | 鼠标位置参与粒子计算，改变粒子位置或鼠标附近连线 | 粒子靠近鼠标，鼠标附近出现额外连线 |
| `FX_HOVER_SURFACE` | 鼠标进入目标后改变边框、阴影、透明度或位置 | 卡片上浮、边框变亮、阴影增强 |
| `FX_HOVER_CONTROL` | 控件自身的 hover、focus 或 active 反馈 | 按钮扫光、日历日期高亮、导航下划线 |
| `FX_FOCUS_STATE` | 键盘焦点或辅助技术焦点反馈，不依赖鼠标 | focus ring、边框和颜色变化 |

后续讨论中，“鼠标效果”默认只指 `FX_CURSOR_SPOTLIGHT` 和 `FX_CURSOR_PARTICLE`。普通边框、阴影、按钮扫光和日期高亮属于悬停或控件状态，不与鼠标跟随光晕混为一谈。

### 1.3 层数计算规则

1. 每一个独立的 CSS `linear-gradient` 或 `radial-gradient` 计为一个静态背景子层。
2. `mask-image`、`opacity`、`transform` 和 `backdrop-filter` 是合成或材质属性，不单独算背景层，但要记录其性能影响。
3. 一个 Canvas 动画整体计为一个动态背景层，不按粒子数量拆算。
4. 卡片填充和卡片内部光晕不计入全局背景层，除非它们被提升为覆盖整个路由的公共层。
5. 同一类效果在多个实例出现时，记录“效果类型”和“实例数量”两项。例如：`FX_CURSOR_SPOTLIGHT` 1 类、7 个项目卡片实例。

### 2.4 共享能力决定

本阶段只抽取静态共享能力：新建 `frontend/src/components/KnowledgeMapBackground.vue`，同时提供 `BG_BASE_DARK` 和 `BG_GLOW_GLOBAL`，固定铺满路由、`pointer-events: none`，不包含 Canvas、不注册鼠标事件、不启动动画。Dashboard 和 TradeSim 都挂载这一层，避免同一套 CSS 渐变在两个路由重复维护。

Dashboard 的 `BG_PARTICLE_AUTO` 仍保留在 `frontend/src/views/Dashboard.vue` 的 Hero 内，因为它与 Hero 尺寸、粒子鼠标响应和 Hero 局部光晕绑定；把它提升为全局能力会让 TradeSim 等数据密集页面承担无收益的持续渲染。

现有 `frontend/src/components/StarfieldBackground.vue` 继续作为 Bills 等页面的既有动态背景实现，本阶段不把它和 Dashboard 粒子实现强行合并，也不让同一路由同时运行两套粒子 Canvas。后续若要统一粒子实现，应另立阶段，先完成参数、降级策略和性能基线再改。

TradeSim 的布局根、模拟页、收藏库页和详情页已移除覆盖共享背景的 `#f0f2f5`，保留侧栏、表单、表格、图表等内容卡片的独立表面。这样先完成共享背景能力，不把“背景并入”和“全量深色主题重做”混成一个高风险变更。

## 3. Hero 粒子鼠标响应处理记录

### 3.1 处理结论

这部分可以修复，不删除。

原因：自动粒子动画已经在使用，鼠标分支是同一套粒子引擎的自然扩展。当前问题是事件绑定位置不对，而不是粒子逻辑本身不可用。

### 3.2 实施方案

1. 把模板中的 `@mousemove` 和 `@mouseleave` 从 `.hero-backdrop` 移到 `.hero-panel`。
2. 保留 `.hero-backdrop` 和 `.constellation-canvas` 的 `pointer-events: none`，让它们只负责视觉，不拦截按钮、输入框和卡片事件。
3. 继续使用 Canvas 的 `getBoundingClientRect()` 把 Hero 面板事件坐标转换为 Canvas 坐标。
4. 验证鼠标位于标题、按钮、天气卡片、日历卡片和 Hero 空白区域时，粒子响应都能工作，控件点击和日历交互不受影响。
5. 鼠标离开整个 `.hero-panel` 后，清空 `bgMouse`，避免粒子继续追逐旧坐标。
6. 检查触摸设备和 `prefers-reduced-motion`，在不支持或不适合运行时降级为自动粒子或静态背景。
7. 如果修复后效果仍然过于微弱，再单独调整半径、透明度和吸引强度，不与背景层清理混在同一项中。

### 3.3 不采用的方案

不把 `.hero-backdrop` 改成可命中的透明覆盖层。这样虽然能快速接收事件，但会让背景层参与命中测试，后续容易和 Hero 内的按钮、卡片、表单产生层级问题。

### 3.4 当前实现状态

- `frontend/src/views/Dashboard.vue` 已将 `@mousemove`、`@mouseleave` 从 `.hero-backdrop` 移到 `.hero-panel`。
- Canvas 坐标仍通过 `getBoundingClientRect()` 计算，没有改变粒子坐标系。
- 已增加 `prefers-reduced-motion` 监听：减少动态效果时停止粒子动画，恢复后重新启动；页面卸载时移除监听并取消动画帧。
- `npm.cmd --prefix frontend run build` 已通过；浏览器已确认 Hero 容器可接收事件、背景视觉层不会拦截事件，粒子分支仍按源码中的同一 Canvas 坐标逻辑运行。

## 4. 后续界面修改约定

### 4.1 页面按需启用效果

- 只要深色背景：启用 `BG_BASE_DARK`，不自动启用粒子和鼠标光晕。
- 需要空间感：追加一到两组 `BG_GLOW_GLOBAL` 或 `BG_GLOW_SECTION`。
- 需要持续动态：明确登记 `BG_PARTICLE_AUTO`，每个路由最多保留一套全屏或 Hero 粒子动画。
- 需要交互反馈：只在确实可点击或可探索的目标上启用 `FX_CURSOR_SPOTLIGHT`。
- 不需要鼠标交互的页面，不保留无效的鼠标监听代码。

### 4.2 共享背景约定

- `StarfieldBackground.vue` 和 Dashboard 自己的 `constellation-canvas` 不能在同一路由同时运行。
- 后续如果抽取公共背景，必须明确它使用哪一套粒子实现，其他页面只通过配置启用或关闭。
- 静态共享背景使用 `frontend/src/components/KnowledgeMapBackground.vue`；共享能力不应顺带启动粒子、鼠标监听或滚动监听。
- 背景层必须是 `pointer-events: none`，交互监听放在真正的内容容器或路由根节点上。
- 每套动态效果都要有清理逻辑，页面卸载时移除事件监听并取消动画帧。

### 4.3 视觉和性能约定

- 先保证背景和内容的对比度，再追求玻璃、模糊和光晕。
- 不为看不见或没有交互价值的效果保留持续动画。
- `backdrop-filter`、大面积阴影和 Canvas 是重点性能检查对象。
- 动态效果必须考虑 `prefers-reduced-motion`。
- 每次删除或新增效果，都在本文档记录启用范围、实际效果和验证结果。

### 4.4 当前验证边界

- 已完成桌面浏览器实况检查：Dashboard、TradeSim `/simulate`、`/dashboard`、`/detail/1` 均可加载；共享背景各为 1 个实例，TradeSim 视图根节点可透出共享背景。
