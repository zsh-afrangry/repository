## 1. 这是什么（30 秒）

KnowledgeMap 是**一个人的个人门户**，把几个自用项目聚合到一个前端入口：

| 模块 | 路由 | 说明 |
|---|---|---|
| 门户首页 | `/` | 项目卡片墙。**卡片与统计数字是静态占位，没有接数据库**（见第 5 节） |
| 记账 | `/bills` | 收支记录、标签体系、月度汇总。**这是唯一在用的真实业务模块** |
| 储物间 | `/vault` | **归档页**，放早期落地页设计的静态草稿，不是产品功能 |
| 笔记 | `/notes` 等 4 条 | Markdown 阅读器 |
| **TradeSim** | `/tradesim/*` | 股票网格回测。原为独立项目，已作为功能模块并入，**不再单独启动** |

技术栈：后端 FastAPI + SQLAlchemy 2.0 + Pydantic v2；前端 Vue 3 + Vite 8 + Tailwind v4；
存储是 **MySQL（结构化索引）+ MongoDB（TradeSim 的大数组）**。

规模参考：后端 **23 条 `/api` 路由**、前端 12 个 `.vue`、`AGENTS.md` 约 1 页×30 的体量。

## 2. 怎么跑起来

### 2.1 前置条件（缺一个都起不来）

### 2.2 `.env`（**本机已有，整节可跳过**；换机器才要填）

> ✅ **在原作者这台电脑上接手：`backend/.env` 已存在且可用，本节整节跳过。**
> 下面这些是"万一你换机器"时用的说明。

`backend/.env.example` 是**完整且键名齐全**的模板（10 个键）。需要填值的 6 个：

```ini
QWEATHER_API_HOST=      # 天气卡片（真实网络调用，没有它天气卡片不可用）
QWEATHER_API_KEY=
DEEPSEEK_API_KEY=       # TradeSim 的 AI 分析（SSE 流式），付费接口
OPENAI_API_KEY=         # 备用 provider，二选一即可
MySQL_USER=
MySQL_PASSWORD=
```

可选的（默认值已够本机用）：`MySQL_HOST_PORT_DATABASE`、`DATABASE_URL`（整串连接串优先级最高）、
以及 `TRADESIM_MONGO_URL` / `TRADESIM_MONGO_DB_NAME`（默认 `mongodb://127.0.0.1:27017` / `tradesim`）。

> **没有 LLM key 会怎样**：门户与记账功能全部正常，只有 TradeSim 的「AI 分析」按钮不可用。
> 也就是说**你可以先不填 LLM key 就开始工作**。

### 2.3 两条启动命令

```powershell
conda activate desheng
cd backend
python main.py            # 后端 → http://127.0.0.1:8010
```

```powershell
cd frontend
npm run dev               # 前端 → http://localhost:3000
```

⚠ **地址写法有讲究，不是笔误**：
- 后端绑 **`127.0.0.1:8010`**（端口可用 `KM_BACKEND_PORT` 覆盖，**主机是硬编码的**）。
- 前端**必须用 `http://localhost:3000`** —— Vite 只监听 IPv6 `::1`，**用 `127.0.0.1:3000` 连不上**。
- 前端把 `/api` 代理到 `http://localhost:8010`（可用 `KM_API_TARGET` 覆盖）。两边端口必须对上，否则每个请求 502。

### 2.4 怎么确认"真的跑起来了"

```powershell
# 后端活着（注意 -NoProxy，否则本机请求会被系统代理拦成 502）
Invoke-WebRequest -Uri "http://127.0.0.1:8010/api/health" -NoProxy
# → 200 {"status":"ok"}
```

⚠ `/api/health` 是**存活探针，不是就绪探针** —— 它**不碰 MySQL 也不碰 Mongo**，数据库挂了它照样返回 200。
要确认数据库真的通，去前端打开 `/bills` 看有没有数据。

### 2.5 改完代码的自检（就这两条）

```powershell
cd frontend
node node_modules\vue-tsc\bin\vue-tsc.js --noEmit        # 期望 exit 0
```

⚠ **必须在 `frontend/` 目录下运行**：这个路径是相对的，在仓库根目录跑会报模块找不到并 exit 1。

```powershell
conda activate desheng
cd backend
python tests\tradesim_grid_strategy_cases.py             # 期望 8 个 PASS
python tests\portal_crud_cases.py                        # 期望 9 个 PASS
```

两个都不是 pytest，是独立脚本，打印 `PASS`/`FAIL` 并在失败时以非零码退出。
`portal_crud_cases.py` 跑在**内存 SQLite** 上，不动你的 MySQL（它在其中插删数据）。

## 5. ⭐ 看起来像 bug，其实是故意的（**别改**）

这是本文最有价值的一节。`AGENTS.md` 里有 **26 处 ⚠ 说明**，下面是**后果最严重、最容易踩**的一批。
改之前请先读对应段落。

| 你会以为 | 实际是 | 在哪 |
|---|---|---|
| 后端绑 `0.0.0.0` 更方便（手机也能用） | **刻意绑 `127.0.0.1`**。本项目**零鉴权**，且含**付费 LLM 接口**，`0.0.0.0` 会让同网段任何设备（含 `curl`）都能调用。**要对外提供必须先加 API-key** | `main.py`、`AGENTS.md` |
| `max_drawdown` 超过 1.0 是计算错了 | **是预期口径**。公式 `(peak - net_value)/peak`，净值被打成负数时必然 > 1。实测最大 1.0452。**禁止 clamp**，那正是"账户爆掉"的信息 | `strategy/base.py`、`grid_trade.py` |
| 6 条老记录的 `grid_step_pct: 0.05` 是错的单位 | **老数据本来就是比例**（2026-02 创建，早于引擎入仓）。**别"修正"数据**。新数据是百分数（`5` = 5%） | `AGENTS.md` TradeSim 段 |
| 详情页 `markLine` 里那个判断多余，可以简化成 `/100` | 那个**值域分支**（`>=1` 当百分数）是**故意的**：无条件 `/100` 会让 6 条老记录的网格线从 **115 条暴涨到 7,004 条** | `TradeSimDetail.vue` |
| 跌破下限该止损 | 口径是**「已建底仓就不再加仓」，跌破下限不是止损信号**，只是"在网格之外"。`grid_trade.py` 里那个 `base_position_opened` 标志就是干这个的 | `grid_trade.py` |
| 详情页读模型比写模型宽松，应该统一 | **故意的双 schema**。最早 2 条记录缺 3 个后加的字段（242 / 2,676 个点全都缺），严格读路径会让详情页 500。**不要删老数据，也不要放宽写路径**（写路径严格才能抓住引擎漏字段） | `schemas/record.py` |

## 7. 环境陷阱（与业务代码无关，但会浪费你半天）

- ⚠ **直接敲 `python` 是个陷阱**：本机它指向 Microsoft Store 的占位程序，**什么都不运行、退出码 9009**，
  并打印"Python was not found; run without arguments to install from the Microsoft Store…"。
  **看到这句话不是你缺依赖，是你忘了 `conda activate desheng`。**
  急着用可以走绝对路径：`C:\Users\afrangry\anaconda3\envs\desheng\python.exe`。
- **`conda` 不在默认 PATH 上**：要么在初始化过的 shell 里 `conda activate desheng`，要么用上面的绝对路径。
- ⚠ **不要执行 `npm install`** —— 本机会触发 `semgrep-core-proprietary.exe` 并拖慢 IDE。
  除非你明确知道自己在做什么，安装依赖这件事交给环境负责人。
  （另外：`frontend/package-lock.json` 是**提交在仓库里的**，前端依赖可复现，别删它。）
- **Vite 只监听 IPv6 `::1`** ⇒ 用 `http://localhost:3000`，`http://127.0.0.1:3000` 会被拒绝。
  `vite preview` 的 `:4173` 同理。
- **PowerShell 里访问本机 HTTP 要加 `-NoProxy`**，否则走系统代理返回 502。
  另外 `TZ=Asia/Shanghai node …` 这种写法在本机**不生效**（PowerShell 会把 `TZ=...` 当成程序名），
  要用 `$env:TZ='Asia/Shanghai'; node …`。
- **环境变量里钉着 `HTTP_PROXY`/`HTTPS_PROXY` 指向一个连不上 PyPI 的本地代理** ⇒ 普通 `pip install` 会**静默挂住**。
  要装包就临时清掉这两个变量并用镜像：
  `python -m pip install <pkg> -i https://pypi.tuna.tsinghua.edu.cn/simple`。
- ⚠ **IDE 报的 "Cannot find module" 全是假阳性** —— IDE 的解释器没指到 `desheng` 环境。
  在终端里代码跑得好好的。把解释器设成上面那个绝对路径即可。
- ⚠ **`.env` 里的 `MySQL_USER`/`MySQL_PASSWORD` 缺失会让整个后端起不来**（记账模块直接不可用），
  但它**不会**在启动时报一句人话给你，表现为请求报错。
- ⚠ **本仓库 `core.autocrlf=true` 且没有 `.gitattributes`**：**工作区是 CRLF、blob 里是 LF**。
  做**内容哈希对比前必须先归一化换行**，否则同一个没改过的文件会算出两个 sha256。
  `git commit` 打印的 LF→CRLF 警告是正常现象，不是文件损坏。
- ⚠ **扫描 `.vue` 找导入时，只扫 `<script>` 块，不要扫全文** ——
  `Notes.vue` 里渲染着整篇 Markdown **文章**，正文的代码示例里有以假乱真的 `import lodash from 'lodash'`
  之类语句，全文 grep 会报出不存在的依赖。
