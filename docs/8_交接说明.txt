## 1. 项目与架构

KnowledgeMap 是个人门户，前端 Vue 3/Vite/Tailwind，后端 FastAPI/SQLAlchemy/Pydantic。TradeSim 已作为内部功能模块合并，不再单独启动。

| 入口 | 用途与当前边界 |
|---|---|
| `/` | 项目门户；项目卡片和部分统计是静态占位，日历、天气、Git 统计有真实请求，不能说整个首页完全没有数据接入 |
| `/bills` | 真实收支记录、标签关联和月汇总 |
| `/notes` | 重定向到 `/Transformer`；另有 `/Database`、`/CNN`、`/MachineLearning` 专题 |
| `/vault` | 早期界面草稿的静态归档页 |
| `/tradesim/*` | 股票网格回测、收藏与详情、AI 分析；年线仍占位，分钟选项尚未在 UI 开放 |

门户后端按层组织，新集成项目按 feature 模块组织。共享一个 MySQL `knowledgemap` 库、Base/engine/SessionLocal；TradeSim 的曲线和流水放 MongoDB `tradesim.simulation_logs`，MySQL 的 `mongo_log_id` 指向它们。不要另建重复数据库会话或独立启动入口。

## 2. 同机启动与配置

### 2.1 环境

- 使用已有 conda 环境 `desheng`。普通 PowerShell 的 `conda` 可能不在 PATH；本机曾有裸 `python` 命中 Microsoft Store 占位程序的问题，可直接使用下方解释器路径。
- MySQL 需要运行并存在 `knowledgemap` 库。启动 lifespan 会 `create_all()` 并调用默认标签种子，**启动不是纯只读操作**；create_all 不会自动 ALTER 已有表。
- MongoDB 服务用于保存与读取回测大对象；收藏列表主要读 MySQL，列表可见不能证明详情数据完整。
- 本机已有依赖与 `backend/.env`，不需要先安装或重填。不要擅自 `npm install`、删 lockfile 或清理 store/cache；需要安装时按项目约定由负责人处理。

### 2.2 两个终端

均从仓库根目录打开终端。

后端：

```powershell
cd backend
& 'C:\Users\afrangry\anaconda3\envs\desheng\python.exe' main.py
```

也可在已初始化的 conda shell 中先 `conda activate desheng`，再于 `backend/` 执行 `python main.py`。

前端：

```powershell
cd frontend
npm.cmd run dev
```

后端默认 `http://127.0.0.1:8010`；主机刻意硬编码为回环地址，端口可用 `KM_BACKEND_PORT` 覆盖。前端配置端口 3000，优先使用启动输出中的 `http://localhost:3000` 地址；**Vite 未硬编码 IPv6 host，历史只监听 ::1 的观测不是永久保证**。若端口被占用或无法连接，检查实际启动输出和监听状态。
Vite 将 `/api` 代理到 `http://localhost:8010`，可用 `KM_API_TARGET` 覆盖；后端端口改变时同步代理目标。CORS 当前允许 `http://localhost:3000`。

### 2.3 配置入口

配置模板为 `backend/.env.example`，真实 `.env` 不入 Git，也不在报告中展示值。

| 用途 | 配置 |
|---|---|
| MySQL 整串连接 | `DATABASE_URL` 优先，其次 `MYSQL_URL`；存在时覆盖分项 |
| MySQL 分项 | `MySQL_USER`、`MySQL_PASSWORD`、`MySQL_HOST`、`MySQL_PORT`、`MySQL_DATABASE`；后面三个是独立键，不存在 `MySQL_HOST_PORT_DATABASE` 组合键 |
| MongoDB | `TRADESIM_MONGO_URL`、`TRADESIM_MONGO_DB_NAME`；默认本机 27017 / tradesim |
| 天气 | `QWEATHER_API_HOST`、`QWEATHER_API_KEY`，调用真实外部服务 |
| AI | DeepSeek 或 OpenAI 兼容配置，以及 TradeSim 专用覆盖项，按模板与 `app/tradesim/core/config.py` 配套设置 key/base URL/model |

MySQL 分项有默认值，不能把“缺某个键”直接等同于固定报错阶段；连接无效可能在启动建表时就失败。缺少可用 AI 配置影响分析功能，不等于账单依赖它。外部服务是否可达需要独立验证。

### 4.2 只有换机器或重装才需要迁移

需要另行安全转移：真实配置、MySQL 业务数据、MongoDB 大对象，并核对 `mongo_log_id` 关联。只迁 MySQL 可能使收藏列表可见而详情失败。导出后还应验证恢复，不把“有导出文件”当作恢复验收。

仓库的 `表结构/*.sql` 不是业务数据备份；其中历史脚本含 DROP，不能直接对真实库执行。启动建表/默认种子也不会恢复账单和回测。
独立 TradeSim 备份在仓库外，集成版不依赖它；本次未验证该备份的恢复能力。

### 4.3 其他本机资产

`UI预览图/` 是设计基线，`tmp_screenshots/` 是临时截图，依赖目录与 `.pnpm-store/`、`.npm-cache/` 是本机资产/缓存；不要为“工作树干净”随意删除。跨机时按需要转移设计资产并重建依赖，同机无需重复搬运。
诊断问题时分别核对环境、配置、数据和代码；既不能看到缺数据就改代码，也不能用旧“测试全绿”排除真实代码缺陷。

## 5. 必须保留的边界

- **本机绑定**：没有鉴权，含付费 AI 接口；对外服务前先设计鉴权，不把 host 改回 `0.0.0.0` 当修复。
- **历史单位兼容**：老 `grid_step_pct` 是比例，新引擎输入是百分数。当前值域猜测仍有 D2，需明确版本/单位；不能全部无条件 `/100` 或随意改历史参数。
- **读写双 schema**：保留宽容的 StoredEquitySnapshot 与严格的新回测写契约；修 D1 的客户端 null 判断，不删老记录或整体放宽写路径。
- **存储一致性**：保留处理 Mongo/SQL 失败的责任，但当前补偿有 D3，不能再把现实现写成不可改的安全保证。先区分 SQL 提交前后与结果不确定的情况。
- **异步数据库**：Motor 必须 await。撤销历史 B5“改 def 并删除 await”的错误配方；同步 SQL 的隔离需管理完整 Session 生命周期。
- **策略口径**：回撤允许超过 100%，禁止截断；D6 的本金峰值问题另修。底仓不重复建立，跌破下限不是止损信号；D7 重入规则另行明确。
- **界面边界**：保留浅色主题代码和占位提示、首页静态展示与 Vault 归档属性；不要把它们当死代码。TradeSim scoped/Markdown 命名空间需保留，isolation 只负责层叠上下文，不能隔离 CSS 选择器。
- **模型边界**：SQLAlchemy Enum 存成员名是当前契约；一个共享 Base/engine。不要靠替换存储值、重建库或删缓存处理无关问题。
- **冻结档案**：根 `已归档/4_项目整理审计与清理计划.txt` 保持原文，旧删除清单与修复建议不直接执行。

## 7. 环境与检查注意事项

- PowerShell 本机 HTTP 使用 `-NoProxy`；环境变量用 `$env:NAME='value'`，不能照抄 Bash 的前缀赋值写法。
- IDE 缺模块提示先检查解释器是否为 desheng，再核实依赖；不能预设所有提示都是假阳性。
- 安装失败先检查环境、代理与权限，不反复绕过限制；本机依赖安装遵循负责人约定。
- 换行转换会影响字节哈希，比较内容前明确 CRLF/LF；不要因此判定文件内容损坏。
- 扫描 Vue 导入只解析 script；模板注释不是可达 UI，Markdown 文章中的代码块不是项目依赖。
- `createWebHistory()` 的生产深链接需要 SPA fallback；本机 Vite 开发可用不代表生产部署已经验收。
