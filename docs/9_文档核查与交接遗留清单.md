## 3. 应进入当前缺陷清单的事项

### D1. 详情页对旧数据的 null 兼容未完成

- 证据：`backend/app/tradesim/schemas/record.py` 的 `StoredEquitySnapshot`（67–69）把缺失字段补为 `None`，序列化成为 JSON `null`。
- `frontend/src/features/tradesim/views/TradeSimDetail.vue` 的 `renderChart`（162）却以 `close_price !== undefined` 判断新版；169 行将 `position_utilization * 100`。
- 本轮直接执行从真实 Vue 文件提取的 `renderChart`，输入旧净值点补齐的三个 `null`：进入新版多图分支，价格/基准为空，仓位被画成 **0**。模型实际序列化也已验证。
- 因此“null 与 undefined 表现一致、不影响图表”的注释和历史结论不成立。应按有效字段/数据版本选择图表，保留缺失值语义；无需删除旧记录或放宽新回测写契约。

### D2. 小于 1% 的新网格步长被误读

- 模拟器 540–549 行允许 `grid_step_pct` 最小 0.01；引擎 `grid_trade.py::_percent_to_ratio`（120–125）始终按百分数除以 100。
- 详情页 184–189 行以数值 `>=1` 猜单位，所以合法新值 **0.5（0.5%）被当成 50%**。
- 本轮实际引擎与实际详情函数分别执行：下限 20、上限 30、`grid_step_pct=0.5`，引擎 **82 个节点**，详情 **2 条线**。
- 原 A1 修复只兼容了常见的 `5` 与历史 `0.05`，没有消除歧义。应为新记录增加明确版本/单位，并保留老记录兼容；禁止直接对全部旧值无条件 `/100` 或改写历史数据。

### D3. 保存补偿存在“提交后删掉有效 Mongo 文档”的窗口

- `backend/app/tradesim/api/v1/records.py::save_record` 先写 Mongo，59 行 `db.commit()`，60 行 `db.refresh()`；67–70 行对后续异常仍执行 SQL rollback 和 Mongo 删除。
- 离线 FakeDB/FakeMongo 故障注入：**commit 已成功，refresh 抛错**，最终接口错误、SQL 已提交、Mongo 被删除。
- commit 后 rollback 无法撤销此前已提交的行，会制造 SQL 指向已删除 Mongo 的断链。当前真实数据没有断链，不代表这个失败路径安全。
- docs/3 §9.2 留下的“保存失败补偿未测试”应当继承为真实遗留。应明确提交边界与提交结果不确定时的恢复策略，再补成功、提交前失败、提交后失败等隔离测试。

### D4. 收藏/AI 可以使用“新表单 + 旧回测结果”

- `TradeSimSimulator.vue::runTest`（413–414）只保留 `currentResponse`；`saveRecord`（443）发送当下可编辑的 `form` 与旧响应；`startAiAnalysis`（355–361）也读取当前表单和旧指标。
- 静态可达路径：完成回测 A → 改股票/网格参数但不重跑 → 收藏或 AI 分析。请求参数与结果失配；不需要网络失败就会发生。
- 应保存一次成功回测对应的不可变请求快照，并让收藏/分析使用同一请求-响应对。本轮未调用付费 AI、未保存任何真实记录。

### D5. PATCH 显式 null 不是“不修改”

- `schemas/bill.py` 71–72 行注释称 `None` 表示不修改；实际 `crud/bill.py::update_bill`（79–82）使用 `model_dump(exclude_unset=True)`，保留显式传入的 null 并赋值。
- 本轮调用真实 schema/CRUD、使用内存 SQLite：`BillUpdate(amount=None)` 导出 `{'amount': None}`，更新触发 **IntegrityError**；真实数据库未被写入。
- 零/负金额校验已完成，但 null 边界未完成。应区分“字段未提供”和“显式清空”，对不允许为空的字段明确拒绝或按约定忽略；可空标签等字段仍需要清空语义。

### D6. 回撤峰值会丢失初始本金锚点

- `strategy/base.py::_record_equity_snapshot`（80–83）先设初始本金，但存在历史点后又仅用历史净值覆盖它。
- 实际引擎纯内存反例：本金 10000，价格 `[10,10]`，底仓比例 0.5、佣金率 0.01、零滑点。净值连续为 **9950、9950**，回撤却从 **0.005 变为 0**。
- 这与保留 `max_drawdown > 1.0` 的既定口径是不同问题。应统一峰值计算的本金基准，不对回撤做截断。

### D7. 跌破下限再重入时跳过跨格处理（待确认策略语义，尚不判定为缺陷）

- `grid_trade.py::execute`（170–179）把 `last_grid_idx == -1` 同时用于初次初始化与价格低于下限，并在该分支更新索引后直接 `continue`。
- 离线真实引擎：等差范围 8–12、8 格、无底仓、每格 100 股、零手续费/滑点，输入 `[10,7,9]`；下跌时买入 9.5/9/8.5/8，反弹到 9 没有卖出，相关网格仓位保留。
- “重复建立底仓”确已被 `base_position_opened` 修复，但不等于区间重入处理完整。若回升穿越应按现有网格规则结算，这是漏处理；修复前明确重入成交口径。**不把跌破下限改成止损。**

### D8. 首页筛选恢复后的卡片可能保持透明（源码确认路径，待浏览器复现）

- `Dashboard.vue` 426–432 按搜索/状态过滤项目；1119–1121 用 `v-for` 创建带 `reveal-item` 的卡片，筛掉后会移除节点。
- `useScrollReveal.ts` 36–38 仅扫描调用瞬间存在的节点，Dashboard 736 行只在 mounted 时调用；3493–3501 的样式要求新增 `revealed` 类才从 opacity 0 变为 1。
- 搜索过滤后清空搜索，会重建此前移除的卡片，而当前没有重新观察新增节点的逻辑。应补这一交互用例，并让动态节点正确被观察或直接可见；本轮没有浏览器实况，故不把推导当已截图复现。
